ชื่อผลงาน

ระบบบริการดิจิทัลเทศบาลนครรังสิต (iService) : ระบบรับและติดตามคำขอรับบริการด้านเทคโนโลยีสารสนเทศ สำหรับบุคลากรเทศบาลนครรังสิต

ระยะเวลาดำเนินการ

ระหว่างเดือนตุลาคม พ.ศ. 2567 ถึงเดือนพฤษภาคม พ.ศ. 2568 (รวมระยะเวลา 8 เดือน) และดำเนินการพัฒนาต่อเนื่องจนถึงปัจจุบัน

- 1 -
แบบแสดงรายละเอียดผลงานที่เป็นผลการดำเนินงานที่ผ่านมาผลงานที่ 2

ความรู้ทางวิชาการ หรือแนวความคิดที่ใช้ในการดำเนินการ

การดำเนินงานพัฒนาระบบบริการดิจิทัลเทศบาลนครรังสิต (iService) ใช้ความรู้ทางวิชาการด้านวิทยาการคอมพิวเตอร์และเทคโนโลยีสารสนเทศในการวิเคราะห์ ออกแบบ พัฒนา ทดสอบ และติดตั้งระบบสารสนเทศขึ้นใหม่ทั้งระบบ โดยมีแนวคิดสำคัญคือการปรับกระบวนงานรับคำขอรับบริการด้านเทคโนโลยีสารสนเทศของบุคลากรภายในเทศบาลจากรูปแบบเดิมที่ติดต่อด้วยโทรศัพท์ วาจา หรือข้อความส่วนตัวผ่านแอปพลิเคชัน LINE ซึ่งไม่มีการบันทึกและติดตามผลอย่างเป็นระบบ ให้เป็นกระบวนงานดิจิทัลที่มีข้อมูลกลาง ตรวจสอบได้ และสนับสนุนการบริหารจัดการภาระงานด้านไอทีขององค์กรอย่างมีประสิทธิภาพ

ความรู้และแนวคิดที่ใช้ประกอบด้วยหลักการวิเคราะห์และออกแบบระบบสารสนเทศตามวงจรพัฒนาระบบ (Systems Development Life Cycle: SDLC) แบบ Iterative การออกแบบฐานข้อมูลเชิงสัมพันธ์ตามหลัก Normalization ถึงระดับ Third Normal Form เพื่อลดความซ้ำซ้อนของข้อมูลและรองรับโครงสร้างหน่วยงาน 4 ระดับ (สำนัก/กอง ส่วน ฝ่าย/กลุ่มงาน งาน) การพัฒนาเว็บแอปพลิเคชันด้วยภาษา PHP ร่วมกับสถาปัตยกรรมแบบ MVC บางส่วนควบคู่กับโครงสร้างเดิม การเชื่อมต่อฐานข้อมูล MySQL/MariaDB ด้วย MySQLi และ PDO Prepared Statement การออกแบบระบบบัญชีผู้ใช้งานและกำหนดสิทธิ์การใช้งานตามบทบาท (Role-Based Access Control) แบ่งเป็นผู้ดูแลระบบ เจ้าหน้าที่ และผู้ใช้งานทั่วไป การพัฒนาแบบฟอร์มรับคำขอรับบริการ 10 ประเภทแบบ Dynamic Form และการออกแบบระบบติดตามสถานะคำขอด้วยเลขที่อ้างอิงและ QR Code

นอกจากนี้ยังประยุกต์ใช้ความรู้ด้านการพัฒนาส่วนติดต่อผู้ใช้งานด้วย HTML, CSS, JavaScript และ Tailwind CSS ให้รองรับการแสดงผลแบบ Responsive บนทุกอุปกรณ์ การใช้ PHPMailer สำหรับแจ้งเตือนผ่านอีเมล และ LINE Messaging API ผ่าน LINE Login Flutter Framework (LIFF) สำหรับแจ้งเตือนแบบ Push Message การใช้ Cron Job บนเซิร์ฟเวอร์สำหรับงานแจ้งเตือนตามรอบเวลา รวมถึงการยกระดับความมั่นคงปลอดภัยสารสนเทศตามแนวทาง OWASP Top 10 เช่น Password Hashing, Session-based Authentication, SQL Injection Prevention และการบันทึก User Action Log

แนวคิดหลักของผลงานนี้สอดคล้องกับนโยบาย Digital Government และ Smart Governance ที่มุ่งนำเทคโนโลยีดิจิทัลมาใช้ยกระดับกระบวนงานภาครัฐให้รวดเร็ว โปร่งใส ตรวจสอบได้ และมีข้อมูลสนับสนุนการตัดสินใจของผู้บริหาร อีกทั้งยังเป็นฐานข้อมูลกลางที่สามารถเชื่อมโยงและขยายผลไปสู่การพัฒนาระบบสารสนเทศอื่นของเทศบาลนครรังสิตในระยะต่อมา เช่น ระบบติดตามคุณภาพอากาศ PM2.5 และระบบจองห้องประชุม

แบบแสดงรายละเอียดผลงานที่เป็นผลการดำเนินงานที่ผ่านมาผลงานที่ 2

สรุปสาระสำคัญและระเบียบกฎหมายที่เกี่ยวข้อง

สภาพปัญหาและความจำเป็นในการดำเนินงาน

เดิมการขอรับบริการด้านเทคโนโลยีสารสนเทศของบุคลากรเทศบาลนครรังสิตดำเนินการในรูปแบบไม่เป็นทางการ เช่น การโทรศัพท์ การติดต่อด้วยวาจา หรือการส่งข้อความผ่านแอปพลิเคชัน LINE ส่วนตัวถึงเจ้าหน้าที่ผู้ดูแลงานด้านไอที ซึ่งไม่มีการบันทึกข้อมูลคำขอเป็นระบบ ไม่มีเลขที่อ้างอิง และไม่มีการกำหนดผู้รับผิดชอบหรือลำดับความสำคัญที่ชัดเจน ส่งผลให้เกิดความล่าช้าในการดำเนินงาน คำขอบางส่วนตกหล่นหรือถูกลืม และไม่สามารถตรวจสอบสถานะหรือประวัติการให้บริการย้อนหลังได้

ด้วยปริมาณคำขอรับบริการด้านไอทีที่เพิ่มขึ้นอย่างต่อเนื่อง ครอบคลุมงานหลากหลายประเภท ทั้งงานอีเมล งานเครือข่ายและอินเทอร์เน็ต งานซ่อมบำรุงอุปกรณ์คอมพิวเตอร์และเครื่องพิมพ์ งานออกแบบสื่อกราฟิกและ QR Code งานถ่ายภาพ/วิดีโอ และงานสนับสนุนกิจกรรมต่าง ๆ ของเทศบาล จึงมีความจำเป็นต้องพัฒนาระบบกลางที่สามารถรองรับการรับคำขอจากบุคลากรทุกหน่วยงาน บันทึกข้อมูลอย่างเป็นระบบ มอบหมายงานให้ผู้รับผิดชอบได้อย่างถูกต้อง และสามารถสรุปรายงานเชิงปริมาณเพื่อใช้ในการบริหารจัดการภาระงานและวางแผนทรัพยากรด้านไอทีขององค์กร

นอกจากนี้ ผู้ขอรับบริการเองก็ไม่มีช่องทางในการติดตามความคืบหน้าของคำขอที่ได้แจ้งไปแล้ว ต้องติดต่อสอบถามซ้ำกับเจ้าหน้าที่ ทำให้เกิดภาระงานซ้ำซ้อนทั้งสองฝ่าย จึงมีความจำเป็นต้องพัฒนาระบบติดตามสถานะคำขอด้วยตนเอง (Self-Service Tracking) ผ่านเลขที่อ้างอิงหรือ QR Code พร้อมการแจ้งเตือนความคืบหน้าผ่านอีเมลและ LINE เพื่อลดภาระงานของเจ้าหน้าที่และเพิ่มความโปร่งใสในการให้บริการแก่บุคลากรภายในองค์กร

ความยากและความซับซ้อนของการดำเนินงาน

  1. การวิเคราะห์และรวบรวมความต้องการ (Requirement Analysis) จากบุคลากรในหน่วยงานต่าง ๆ ของเทศบาลซึ่งมีลักษณะงาน 10 ประเภทที่แตกต่างกันโดยสิ้นเชิง ทั้งในด้านข้อมูลที่ต้องกรอก เงื่อนไขการอนุมัติ และผู้รับผิดชอบ ทำให้ต้องออกแบบโครงสร้างข้อมูลให้มีความยืดหยุ่นเพียงพอที่จะรองรับทุกประเภทบริการในระบบเดียวกัน
  2. การออกแบบฐานข้อมูลให้รองรับโครงสร้างหน่วยงานของเทศบาลที่มี 4 ระดับ (สำนัก/กอง → ส่วน → ฝ่าย/กลุ่มงาน → งาน) ซึ่งต้องนำมาประกอบกับการกำหนดผู้รับมอบหมายงานและสายการอนุมัติให้สอดคล้องกับโครงสร้างองค์กรจริง
  3. การออกแบบระบบบัญชีผู้ใช้งานและกำหนดสิทธิ์การเข้าถึงข้อมูลตามบทบาท (Role-Based Access Control) เป็น 3 ระดับ ได้แก่ ผู้ดูแลระบบ (admin) เจ้าหน้าที่ผู้รับผิดชอบงาน (staff) และผู้ใช้งานทั่วไป (user) โดยต้องควบคุมสิทธิ์การเข้าถึงข้อมูลคำขอ การมอบหมายงาน และรายงานให้เหมาะสมกับแต่ละบทบาทอย่างรัดกุม
  4. การพัฒนาแบบฟอร์มรับคำขอรับบริการแบบ Dynamic Form ทั้ง 10 ประเภท ซึ่งแต่ละประเภทมีชุดข้อมูลและองค์ประกอบของฟอร์มที่แตกต่างกัน เช่น การเลือกวันเวลาแบบ Time Picker สำหรับงานถ่ายภาพและงานพิธีกร การอัปโหลดไฟล์แนบสำหรับงานออกแบบกราฟิก โดยต้องออกแบบโครงสร้างฐานข้อมูลและส่วนติดต่อผู้ใช้ให้รองรับการขยายประเภทบริการในอนาคตได้ง่าย
  5. การออกแบบและพัฒนาระบบติดตามสถานะคำขอ (Ticket Tracking) ด้วยเลขที่อ้างอิงและ QR Code ให้ผู้ขอรับบริการสามารถตรวจสอบสถานะได้เองโดยไม่ต้องเข้าสู่ระบบ พร้อมแสดงไทม์ไลน์ขั้นตอนการดำเนินงานและรายชื่อผู้รับมอบหมายงานทั้งหมด
  6. การเชื่อมต่อ LINE Messaging API ผ่าน LINE Front-end Framework (LIFF) เพื่อแจ้งเตือนสถานะคำขอและงานที่ได้รับมอบหมายแบบ Push Message ซึ่งต้องศึกษาการขอ Channel Access Token การจัดการ LINE User ID ของผู้ใช้แต่ละคน และการเขียน Cron Job สำหรับแจ้งเตือนล่วงหน้าตามรอบเวลาที่กำหนด
  7. การแก้ไขปัญหาทางเทคนิคเฉพาะของเครื่อง Production Server บน cPanel ที่ Apache ทำการตัด (strip) HTTP Header ประเภท Authorization ออกก่อนส่งถึง PHP ทำให้การยืนยันตัวตนผ่าน Bearer Token ของ API ใช้งานไม่ได้ ต้องวิเคราะห์หาสาเหตุและแก้ไขด้วยการส่งค่าผ่าน Environment Variable ใน .htaccess แล้วอ่านค่าด้วย getenv() ในฝั่ง PHP
  8. การออกแบบส่วนติดต่อผู้ใช้งาน (UI/UX) ให้ใช้งานง่ายสำหรับบุคลากรทุกระดับที่มีความคุ้นเคยกับเทคโนโลยีแตกต่างกัน โดยใช้ Tailwind CSS ให้รองรับการแสดงผลแบบ Responsive บนคอมพิวเตอร์และอุปกรณ์เคลื่อนที่ ร่วมกับ SweetAlert2 เพื่อแจ้งผลการทำงานให้ชัดเจนและเป็นมิตรกับผู้ใช้
  9. การพัฒนา Cron Job บนเซิร์ฟเวอร์สำหรับส่งการแจ้งเตือนงานตามแผนตามรอบเวลาที่กำหนด (ก่อนถึงกำหนด 1 วัน / ก่อนถึงกำหนด 1 ชั่วโมง / เมื่อเริ่มงาน) ซึ่งระหว่างพัฒนาพบปัญหา Syntax ของ PHP Docblock (/** */) ตีความรูปแบบเวลา */15 ในคอมเมนต์เป็นการปิดคอมเมนต์ก่อนกำหนด ทำให้ต้องปรับใช้คอมเมนต์แบบ # แทนเพื่อแก้ไขปัญหา

ผลลัพธ์และคุณค่าที่เกิดขึ้น

  1. เทศบาลนครรังสิตมีระบบกลางสำหรับรับคำขอรับบริการด้านเทคโนโลยีสารสนเทศจากบุคลากรทุกหน่วยงาน ครอบคลุม 10 ประเภทบริการ สามารถเข้าใช้งานผ่านเว็บเบราว์เซอร์ได้ตลอด 24 ชั่วโมง โดยไม่ต้องติดต่อด้วยวาจาหรือโทรศัพท์อีกต่อไป
  2. ผู้ขอรับบริการสามารถติดตามสถานะคำขอของตนเองได้ตลอดเวลาผ่านเลขที่อ้างอิงหรือ QR Code ลดภาระงานของเจ้าหน้าที่ในการตอบคำถามเรื่องความคืบหน้าซ้ำซาก
  3. ผู้บริหารและหัวหน้างานมีข้อมูลสถิติคำขอรับบริการแยกตามประเภทบริการ หน่วยงาน และช่วงเวลา ซึ่งสามารถนำไปใช้วางแผนทรัพยากรบุคคลและงบประมาณด้านไอทีของเทศบาลในแต่ละปีงบประมาณ
  4. มีการแจ้งเตือนสถานะคำขอแบบทันที (Real-time) ผ่านอีเมลและ LINE ทำให้ผู้ขอรับบริการและผู้รับมอบหมายงานทราบความคืบหน้าได้อย่างรวดเร็ว ลดความล่าช้าในการประสานงาน

  2. พระราชบัญญัติว่าด้วยธุรกรรมทางอิเล็กทรอนิกส์ พ.ศ. 2544 และที่แก้ไขเพิ่มเติม
  3. พระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA)

  5. ระเบียบสำนักนายกรัฐมนตรีว่าด้วยงานสารบรรณ พ.ศ. 2526 และที่แก้ไขเพิ่มเติม (สำหรับการกำหนดเลขที่อ้างอิงคำขอและการจัดเก็บเอกสารอิเล็กทรอนิกส์)

  1. ศึกษาสภาพปัญหาและวิเคราะห์ความต้องการ (Requirement Analysis) โดยการสัมภาษณ์และสำรวจรูปแบบการขอรับบริการด้านไอทีจากบุคลากรของหน่วยงานต่าง ๆ ภายในเทศบาลนครรังสิต เพื่อกำหนดประเภทบริการ ขอบเขตของระบบ และกลุ่มผู้ใช้งาน
  2. ออกแบบโครงสร้างฐานข้อมูล (Database Design) ในรูปแบบ Entity-Relationship Diagram ให้รองรับโครงสร้างหน่วยงาน 4 ระดับ ประเภทบริการ 10 ประเภท และความสัมพันธ์ระหว่างคำขอ ผู้ขอ ผู้รับมอบหมายงาน และสถานะการดำเนินงาน ตามหลักการ Normalization
  3. ออกแบบและพัฒนาระบบบัญชีผู้ใช้งานและการกำหนดสิทธิ์การเข้าถึงข้อมูลตามบทบาท (Role-Based Access Control) แบ่งเป็น admin, staff และ user พร้อมระบบยืนยันตัวตนแบบ Session-based Authentication และการจัดเก็บรหัสผ่านด้วยวิธี Hashing
  4. พัฒนาส่วนรับคำขอรับบริการสำหรับผู้ใช้งาน (Public Request Form) ในรูปแบบ Dynamic Form ที่ปรับเปลี่ยนชุดข้อมูลตามประเภทบริการที่เลือกทั้ง 10 ประเภท พร้อมการตรวจสอบความถูกต้องของข้อมูล (Validation) ทั้งฝั่ง Client และฝั่ง Server
  5. พัฒนาระบบติดตามสถานะคำขอ (Ticket Tracking System) โดยออกเลขที่อ้างอิงอัตโนมัติให้แต่ละคำขอ พร้อมสร้าง QR Code สำหรับเข้าสู่หน้าติดตามสถานะ และออกแบบหน้าแสดงไทม์ไลน์ขั้นตอนการดำเนินงานให้ผู้ขอรับบริการตรวจสอบได้ด้วยตนเองโดยไม่ต้องเข้าสู่ระบบ
  6. พัฒนาระบบแจ้งเตือนผ่านอีเมลด้วยไลบรารี PHPMailer เพื่อส่งอีเมลแจ้งผู้ขอรับบริการและเจ้าหน้าที่ที่เกี่ยวข้องโดยอัตโนมัติเมื่อมีการสร้างคำขอใหม่ มอบหมายงาน หรือมีการเปลี่ยนแปลงสถานะคำขอ

ผลสำเร็จของงาน

เชิงปริมาณ

  1. พัฒนาระบบ iService แล้วเสร็จสมบูรณ์และเปิดให้บริการจริงที่ https://iservice.rangsitcity.go.th/ ครบทั้ง 10 ประเภทบริการตามที่ออกแบบไว้ ภายในระยะเวลา 8 เดือนตามแผนที่กำหนด
  2. ทุกคำขอที่ยื่นผ่านระบบได้รับเลขที่อ้างอิงและ QR Code สำหรับติดตามสถานะครบ 100%
  3. ระบบส่งการแจ้งเตือนสถานะผ่านอีเมลและ LINE ได้ภายในเวลาไม่เกิน 5 นาทีหลังมีการเปลี่ยนแปลงสถานะ เป็นไปตามเป้าหมายที่กำหนด
  4. ระบบรองรับบัญชีผู้ใช้งานของบุคลากรเทศบาลครบทุกหน่วยงาน ครอบคลุมโครงสร้าง 4 ระดับ (สำนัก/กอง ส่วน ฝ่าย/กลุ่มงาน งาน)
  5. Cron Job แจ้งเตือนงานตามแผนทำงานอัตโนมัติทุก 15 นาที ครอบคลุมการแจ้งเตือนทั้ง 3 รูปแบบ (ก่อนถึงกำหนด 1 วัน / ก่อนถึงกำหนด 1 ชั่วโมง / เมื่อเริ่มงาน) โดยไม่มีการแจ้งเตือนซ้ำซ้อน
  6. มีรายงานสถิติคำขอรับบริการแยกตามประเภทบริการ หน่วยงาน และช่วงเวลา สำหรับผู้บริหารใช้ประกอบการบริหารจัดการ
  7. ลดระยะเวลาตั้งแต่รับคำขอจนถึงมอบหมายงานให้ผู้รับผิดชอบลงอย่างชัดเจน เมื่อเทียบกับกระบวนงานเดิมที่ใช้การติดต่อด้วยวาจาหรือโทรศัพท์

เชิงคุณภาพ

  1. บุคลากรของเทศบาลมีความพึงพอใจต่อการใช้งานระบบในระดับดีถึงดีมาก เนื่องจากสามารถยื่นคำขอและติดตามสถานะได้ด้วยตนเองตลอด 24 ชั่วโมง
  2. ระบบมีความมั่นคงปลอดภัยของข้อมูลตามแนวทาง OWASP Top 10 ผ่านการใช้ Prepared Statement, Password Hashing และ Session-based Authentication
  3. ส่วนติดต่อผู้ใช้งานใช้งานง่าย เข้าใจง่าย และรองรับการแสดงผลแบบ Responsive ทั้งบนคอมพิวเตอร์และอุปกรณ์เคลื่อนที่
  4. ข้อมูลคำขอรับบริการมีความถูกต้อง ครบถ้วน และตรวจสอบย้อนหลังได้ทุกคำขอ ลดความผิดพลาดจากการสื่อสารด้วยวาจา
  5. แนวคิดและโครงสร้างของระบบถูกนำไปใช้เป็นต้นแบบ (Template) ในการพัฒนาระบบติดตามคุณภาพอากาศ PM2.5 ของเทศบาล ซึ่งใช้รูปแบบหน้าจอ การแจ้งเตือนผ่าน LINE และ Cron Job ในรูปแบบเดียวกัน
  6. ภาพลักษณ์ของเทศบาลนครรังสิตด้านการให้บริการดิจิทัลภายในองค์กรดีขึ้น สอดคล้องกับนโยบาย Digital Government และ Smart Governance

การนำไปใช้ประโยชน์

  1. บุคลากรทุกหน่วยงานของเทศบาลใช้ระบบ iService เป็นช่องทางหลักในการขอรับบริการด้านเทคโนโลยีสารสนเทศ แทนการติดต่อด้วยวาจาหรือโทรศัพท์แบบเดิม
  2. ผู้บริหารใช้ข้อมูลสถิติจากระบบในการวางแผนทรัพยากรบุคคลและงบประมาณด้านไอทีในแต่ละปีงบประมาณ
  3. เจ้าหน้าที่ผู้ดูแลงานด้านไอทีใช้ระบบบริหารจัดการภาระงาน มอบหมายงาน และติดตามความคืบหน้าได้สะดวกและเป็นระบบมากขึ้น
  4. ผู้ขอรับบริการสามารถติดตามสถานะคำขอด้วย QR Code ได้ด้วยตนเอง โดยไม่ต้องติดต่อสอบถามเจ้าหน้าที่
  5. โครงสร้างฐานข้อมูลและสถาปัตยกรรมของระบบถูกนำไปประยุกต์ใช้ในการพัฒนาระบบติดตามคุณภาพอากาศ (PM2.5 Monitoring System) ของเทศบาลในลำดับต่อมา
  6. แนวคิดการแจ้งเตือนผ่าน LINE Messaging API/LIFF และ Cron Job ของระบบนี้ ถูกนำไปใช้เป็นต้นแบบในการพัฒนาระบบแจ้งเตือนงานตามแผนของระบบจองห้องประชุมเทศบาลนครรังสิต (ผลงานที่ 1)
  7. ใช้เป็นกรณีศึกษาในการถ่ายทอดความรู้ด้านการพัฒนาระบบสารสนเทศให้แก่บุคลากรรุ่นใหม่ของเทศบาล
  8. ช่วยลดการใช้กระดาษและขั้นตอนเอกสารในกระบวนงานภายใน สนับสนุนนโยบาย Digital Government และ Smart City ของเทศบาลนครรังสิต

ความยุ่งยากในการดำเนินการ / ปัญหา / อุปสรรค

  1. บุคลากรในหน่วยงานต่าง ๆ มีรูปแบบการทำงานและความต้องการที่แตกต่างกัน การรวบรวมความต้องการ (Requirement Analysis) จึงใช้เวลานานและต้องปรับปรุงหลายครั้ง
  2. โครงสร้างหน่วยงานของเทศบาลมี 4 ระดับและมีความซับซ้อน การกำหนดสิทธิ์ผู้ใช้งานและสายการมอบหมายงานให้สอดคล้องกับโครงสร้างจริงทำได้ยาก
  3. เครื่องแม่ข่าย Production บน cPanel มีการตั้งค่า Apache ที่ตัด (strip) HTTP Header ประเภท Authorization ออกก่อนส่งถึง PHP ทำให้การยืนยันตัวตนของ API ด้วย Bearer Token ใช้งานไม่ได้
  4. สภาพแวดล้อม Local (XAMPP) และ Production มีความแตกต่างกันทั้งเวอร์ชัน PHP การตั้งค่า .htaccess และโครงสร้าง Path ของไฟล์อัปโหลด ทำให้ต้องทดสอบซ้ำหลายรอบก่อนใช้งานจริง
  5. การเชื่อมต่อ LINE Messaging API ผ่าน LIFF มีข้อจำกัดด้านการขอ Channel Access Token และการผูกบัญชี LINE ส่วนตัวของผู้ใช้งานแต่ละคนเข้ากับระบบ
  6. ผู้พัฒนาดำเนินการเพียงผู้เดียว ต้องรับผิดชอบครบทุกขั้นตอนตั้งแต่การวิเคราะห์ ออกแบบ พัฒนา ทดสอบ จนถึงดูแลระบบหลังใช้งานจริง จำเป็นต้องบริหารเวลาและจัดลำดับความสำคัญของงานอย่างรอบคอบ
  7. บุคลากรผู้ใช้งานมีทักษะด้านเทคโนโลยีที่แตกต่างกัน บางส่วนไม่คุ้นเคยกับการใช้งานระบบออนไลน์ ต้องออกแบบส่วนติดต่อผู้ใช้งานให้ใช้งานง่ายและจัดทำคำแนะนำการใช้งานเพิ่มเติม
  8. ระหว่างพัฒนา Cron Job พบปัญหา PHP Docblock รูปแบบ (/** */) ตีความรูปแบบเวลา */15 ในคอมเมนต์เป็นการปิดคอมเมนต์ก่อนกำหนด ทำให้สคริปต์ไม่ทำงานตามเวลาที่ตั้งไว้
  9. การพัฒนาแบบฟอร์มรับคำขอแบบ Dynamic Form ทั้ง 10 ประเภทที่มีชุดข้อมูลแตกต่างกัน ทำให้โครงสร้างฐานข้อมูลและ Logic การตรวจสอบข้อมูลมีความซับซ้อนสูง ต้องออกแบบให้รองรับการขยายประเภทบริการในอนาคต

วิธีดำเนินการแก้ไขปัญหา / อุปสรรค จนเกิดผลสำเร็จ

  1. จัดประชุมและลงพื้นที่สัมภาษณ์ตัวแทนของแต่ละหน่วยงาน รวบรวมแบบฟอร์ม/เอกสารคำขอที่ใช้อยู่เดิม นำมาวิเคราะห์จัดกลุ่มเป็น 10 ประเภทบริการ และจัดทำ Prototype ให้ผู้ใช้งานทดลองและให้ข้อเสนอแนะก่อนพัฒนาจริง เพื่อลดการแก้ไขซ้ำในขั้นตอนถัดไป
  2. ออกแบบตารางฐานข้อมูลแยกตามระดับหน่วยงาน (สำนัก/กอง ส่วน ฝ่าย/กลุ่มงาน งาน) ในรูปแบบ Hierarchical พร้อมเชื่อมโยงกับตารางผู้ใช้งานและสิทธิ์การใช้งาน (RBAC) ผ่าน Foreign Key ทำให้สามารถกำหนดสิทธิ์และมอบหมายงานตามสายบังคับบัญชาได้อย่างถูกต้อง
  3. วิเคราะห์หาสาเหตุจาก Apache Error Log พบว่าเครื่องแม่ข่าย Production ตัด Authorization Header ออกก่อนส่งถึง PHP จึงแก้ไขโดยเพิ่ม RewriteRule ใน .htaccess ให้ส่งค่า Header ผ่าน Environment Variable แล้วอ่านค่าด้วยฟังก์ชัน getenv() ในฝั่ง PHP แทนการอ่านจาก Header โดยตรง
  4. สร้างฟังก์ชันกลาง fix_asset_path() สำหรับจัดการ Path ของไฟล์อัปโหลดให้ทำงานถูกต้องทั้งบน Local และ Production พร้อมจัดทำ Checklist รายการตั้งค่าที่แตกต่างกันระหว่างสองสภาพแวดล้อม เพื่อใช้ตรวจสอบก่อน Deploy ทุกครั้ง
  5. ศึกษาเอกสาร LINE Developers อย่างละเอียด สร้าง LINE Official Account และ LIFF App สำหรับระบบโดยเฉพาะ พัฒนาหน้าเชื่อมโยงบัญชี (Account Linking) ให้ผู้ใช้งานยืนยันตัวตนผ่าน LINE Login เพียงครั้งเดียว ระบบจะบันทึก LINE User ID ไว้สำหรับส่งการแจ้งเตือนในครั้งต่อไป
  6. จัดทำแผนงานและจัดลำดับความสำคัญ (Prioritization) โดยพัฒนาโมดูลที่จำเป็นที่สุดก่อน ได้แก่ การรับคำขอและการติดตามสถานะ แล้วจึงพัฒนาโมดูลเสริม เช่น การแจ้งเตือนและรายงาน ตามลำดับ พร้อมใช้ Git ในการบันทึกเวอร์ชันและย้อนกลับโค้ดหากเกิดปัญหา
  7. ออกแบบส่วนติดต่อผู้ใช้งานด้วย Tailwind CSS และ SweetAlert2 ให้มีขั้นตอนน้อย ใช้ข้อความแจ้งเตือนเป็นภาษาไทยที่เข้าใจง่าย พร้อมจัดทำคู่มือการใช้งานแบบภาพประกอบและสอนการใช้งานให้บุคลากรตัวแทนของแต่ละหน่วยงาน
  8. แก้ไขโดยเปลี่ยนจากคอมเมนต์รูปแบบ /** ... */ เป็นคอมเมนต์บรรทัดเดียวแบบ # ในส่วนที่มีการอ้างอิงรูปแบบเวลาของ Cron (เช่น */15) เพื่อป้องกันการตีความปิดคอมเมนต์ก่อนกำหนด และทดสอบการทำงานของ Cron Job ซ้ำจนมั่นใจว่าทำงานตามรอบเวลาที่ถูกต้อง
  9. ออกแบบตารางฐานข้อมูลกลางสำหรับคำขอ (service_requests) ร่วมกับตารางรายละเอียดเฉพาะประเภทบริการ พร้อมแยกไฟล์ฟอร์มเป็นโมดูลย่อยตามประเภทบริการ ทำให้สามารถเพิ่มหรือแก้ไขประเภทบริการในอนาคตได้โดยไม่กระทบโครงสร้างหลักของระบบ

ข้อเสนอแนะ

  1. ควรพัฒนาแดชบอร์ดสรุปภาพรวม (Dashboard) สำหรับผู้บริหารแบบ Real-time แสดงสถิติคำขอ ระยะเวลาดำเนินงานเฉลี่ย และภาระงานของแต่ละหน่วยงาน
  2. ควรขยายการแจ้งเตือนผ่าน LINE ให้ครอบคลุมทุกขั้นตอนของคำขอ ไม่เฉพาะขั้นตอนการมอบหมายงาน
  3. ควรพัฒนาระบบประเมินความพึงพอใจ (Satisfaction Survey) หลังปิดงานแต่ละคำขอ เพื่อใช้เป็นข้อมูลปรับปรุงคุณภาพการให้บริการ
  4. ควรจัดทำคู่มือการใช้งานและจัดอบรมให้บุคลากรใหม่เป็นระยะ เพื่อให้สามารถใช้งานระบบได้อย่างมีประสิทธิภาพ
  5. ควรพิจารณาพัฒนา Progressive Web App (PWA) เพื่อเพิ่มความสะดวกในการใช้งานบนอุปกรณ์เคลื่อนที่
  6. ควรนำแนวคิดและโครงสร้างของระบบ iService ไปขยายผลพัฒนาเป็นระบบกลางสำหรับรับคำขอบริการประเภทอื่นของเทศบาล เช่น งานพัสดุ งานบุคคล และงานซ่อมบำรุงทั่วไป
  7. ควรจัดทำระบบสำรองข้อมูล (Backup) และแผนรองรับภัยพิบัติ (Disaster Recovery) สำหรับฐานข้อมูลของระบบอย่างสม่ำเสมอ
  8. ควรศึกษาแนวทางเชื่อมต่อระบบ iService กับระบบสารบรรณอิเล็กทรอนิกส์ของเทศบาล เพื่อให้การอ้างอิงเลขที่หนังสือและคำขอเป็นมาตรฐานเดียวกัน
